## 二、本批目标

建立服务端权威开奖与可审计账本核心，不接生产钱包、不开放真实资金。

## 三、开发任务

### A. 数学配置

- 建立服务端专用、版本化数学配置。
- 赔付表、线定义、权重、免费游戏、WILD规则、最大赔付全部进入版本对象。
- 配置使用稳定序列化并生成SHA-256。
- 区分`DRAFT`、`FROZEN`、`RETIRED`状态。
- 当前未知参数必须标记为临时候选，不能冒充原版数据。

### B. 服务端权威开奖

- 使用Web Crypto CSPRNG或等价安全随机源。
- 服务端生成盘面、中奖线、SCATTER、WILD倍数、免费游戏和最终赢分。
- 客户端只能提交允许的房间、投注等级、投注倍率和幂等键。
- 客户端提交的盘面、赢分、免费游戏、倍数或余额字段必须被拒绝。
- 每局写入数学版本、请求哈希、结果哈希和可重放审计信息。

### C. API

- `POST /v1/game/sessions`
- `POST /v1/game/spins`
- `GET /v1/game/rounds/{roundId}`
- `GET /v1/game/rules/{mathVersion}`

所有写接口必须进行身份、输入、会话、状态、限额和幂等校验，并使用统一错误结构。

### D. 钱包与账本

- 建立独立测试钱包适配器接口，不连接生产钱包。
- 金额全部使用整数最小单位。
- 下注、派彩分别建立平衡的复式分录。
- 免费游戏下注金额必须为0。
- 余额不足不能创建已结算游戏局。
- 相同玩家和幂等键的重复请求必须返回原局结果，不能二次扣款或派彩。
- 事务失败必须整体回滚，禁止出现“扣款成功但游戏局缺失”等半完成状态。
- 预留乐观锁或等价并发控制，禁止余额变成负数。

### E. 数据库

- 复核现有8张核心表和迁移。
- 只增加本批确实需要的字段、约束和索引。
- 生成新的增量迁移，不修改已经提交的旧迁移。
- 在全新空库验证完整迁移，在已有基线库验证增量迁移。

### F. 测试

至少覆盖：

- 每个普通符号的2/3/4/5连线边界。
- WILD替代和禁止替代SCATTER。
- SCATTER赔付、基础免费局和免费局追加。
- WILD只出现在第2、3、4轴。
- 50/500房间与全部投注档位。
- 重复幂等请求不重复扣款。
- 两个并发Spin不能透支余额。
- 免费局不扣款。
- 借贷总额严格为0。
- 事务注入失败后无残留账务。
- 非法客户端结果字段被拒绝。
- 数学配置哈希稳定。
