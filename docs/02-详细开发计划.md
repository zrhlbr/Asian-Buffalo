# Asian Buffalo 独立网页版详细开发计划

## 项目目标

开发一款正式命名为《Asian Buffalo》的独立网页游戏，玩法研究参考目标AFB《African Buffalo》，采用原创品牌和美术；最终可连接真实资金钱包，并达到可审计、可恢复、安全稳定的工程标准。

当前阶段只开发网页版。项目与ZRH在品牌、公司主体、域名、数据库、钱包密钥、日志、对象存储目录和发布账号上全部隔离。现有服务器、短信和存储可以复用物理资源，但必须使用独立租户、独立数据库、独立凭据和独立备份策略。

## 阶段0：规则与证据冻结（已完成）

交付物：

- 游戏身份核验。
- 5×4、50线、完整可见赔付表。
- 免费游戏与WILD规则。
- 已知/未知参数清单。
- 知识产权边界。

验收：开发团队不得再使用《African Buffalo 2》的30线或97.71% RTP数据。

## 阶段1：网页可玩原型（首版已完成）

功能：

- 5×4盘面、50线结算。
- 50/500房间。
- 投注等级1–10、倍率1/5/10/20/50。
- 普通符号、SCATTER、WILD、免费游戏、追加免费游戏。
- 自动旋转、最大投注、中奖动画阈值。
- 中文规则页和赔付表。
- 手机与桌面响应式布局。
- 明确显示“演示钱包/真钱关闭/RTP待校准”。

本阶段不允许：

- 真实充值、提款和兑换。
- 使用目标游戏原图、音效、Logo或代码。
- 宣称原厂RTP一致。

首版验收记录：代码静态检查、生产构建、部署产物校验和渲染测试均已通过。
受当前预览运行环境限制，浏览器可视化回归留到下一次可用的私有预览中执行；
这不影响构建产物，但在完成可视化回归前不会发布。

## 阶段2：数学引擎与模拟器

建立独立数学包：

- 版本化符号定义、50线定义、赔付表。
- 5条卷轴带或按轴权重表。
- 免费游戏状态机。
- 多WILD倍数明确规则。
- 单局最大赔付和异常保护。
- CSPRNG抽样，无玩家分组调赔率。

仿真要求：

- 开发阶段至少1亿局批量模拟。
- 输出整体RTP、基础局RTP、免费局RTP、命中率、免费游戏频率。
- 输出1×、5×、10×、20×、50×、100×、500×以上赢分概率。
- 输出最大回撤、分位数、置信区间和极端样本。
- 数学配置生成SHA-256哈希；上线后只读。

第一候选RTP建议设为96.50%，但在产品与合规确认前保持可配置候选值，不进入真实资金环境。

## 阶段3：服务端权威局结果

接口：

- `POST /v1/game/sessions`
- `POST /v1/game/spins`
- `GET /v1/game/rounds/{roundId}`
- `GET /v1/game/rules/{mathVersion}`

每局流程：

1. 校验用户、地区、年龄/KYC状态、账户状态、限额和幂等键。
2. 锁定钱包或调用现有钱包的原子投注接口。
3. 使用CSPRNG生成服务端局结果。
4. 按冻结数学版本结算。
5. 同一事务写入局记录、借贷分录、免费局状态和审计摘要。
6. 返回符号、中奖线、赢分、余额和验证字段。

客户端不能提交最终符号、赢分、免费局数量或倍数。

## 阶段4：真钱钱包适配层

钱包必须使用复式记账：

- 玩家可用余额账户。
- 玩家冻结余额账户。
- 游戏清算账户。
- 存款在途账户。
- 提款在途账户。
- 费用与调整账户。

必要规则：

- 所有金额使用整数最小单位，禁止浮点数。
- 每个业务请求使用唯一幂等键。
- 每张凭证借贷合计必须为0。
- 余额不能为负。
- 下注与结算可重试但不可重复入账。
- 每日自动核对游戏局、钱包分录和支付渠道。
- 人工调账必须双人审批并记录原因。

现有钱包接入只通过内部签名API或消息队列，不允许游戏服务直接读写其他项目的钱包表。

## 阶段5：账户与风控

- 独立用户ID与ZRH ID不复用。
- 短信服务复用现有供应商，但使用独立模板、签名、限流键和审计日志。
- 登录密码使用Argon2id或合规身份供应商。
- 管理员强制MFA、IP策略和最小权限。
- 设备指纹、IP、代理、撞库、机器人和多账号风控。
- 存款、提款、投注、登录分别限流。
- 18+/21+年龄门槛按司法辖区配置。
- KYC、AML、制裁名单和可疑交易人工流程。
- 自我排除、冷静期、存款限额、亏损限额和会话提醒。

## 阶段6：原创美术、声音与体验

- 原创水牛主角、草原背景、图标、Logo和动效。
- 不使用目标游戏资源。
- WebP/AVIF纹理、音频分包、弱网降级。
- 目标：首屏资源小于3 MB，完整游戏按需加载。
- 低端安卓浏览器保持30 FPS，高端设备60 FPS。

## 阶段7：测试与安全验收

自动测试：

- 赔付表逐符号测试。
- 50线逐线测试。
- WILD替代、SCATTER、免费游戏、追加测试。
- 幂等、并发、余额不足和超时重试测试。
- 钱包借贷平衡属性测试。
- 断网、重复点击、跨标签页并发测试。
- 1亿局数学回归。

上线前：

- 独立安全审计和渗透测试。
- RNG/数学实验室认证（按目标牌照要求）。
- 灾备演练、账本恢复演练、密钥轮换演练。
- 法律意见、牌照、隐私政策和负责任游戏文本确认。

## 阶段8：灰度与生产

- 先内部演示钱包。
- 再员工白名单、零现金价值。
- 再小额封顶、受限地区灰度。
- 最后才开放真实入金与提款。

任何阶段若数学版本、账本一致性或风控告警未通过，真实资金开关保持关闭。
